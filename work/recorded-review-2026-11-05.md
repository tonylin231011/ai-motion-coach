# 现有记录驱动复盘（2026-11-05）

根因：生产CoachReviewPanel调用buildReview时未提供可信姿态指标，且引擎没有利用已有records.durationMs生成独立的记录复盘，导致全页降级。此次新增reviewRecordedData，在同一buildReview调用内直接读取draft.sessions的现有数据，不要求推断姿态可信度。

计次：每组前3条与末3条周期用时平均对照、变化百分比；从第4条后寻找连续3条同向变化>15%的首个位置。明确是“已记录第N次/条”，不假定漏检后的真实物理次数；不跨无效用时条目拼接连续段、不跨组拼接，不将变快/变慢归因为疲劳。逐条用时展开可核对。组间完成量差异同时标明两组数字，提示目标/结束/漏检等可能影响，不诊断体力。

计时：每组累计保持、最长连续、中断次数，若有上次同动作组则比较时长。明确这些是应用计时，不等于标准姿态时长或中断原因。现有模型/识别器/同步结构不变。

UI：顶部青柠卡在无可信姿态分时显示实际次数或秒数与首条记录复盘，替代大号“无可信姿态评分”。保留姿态尚未评分说明与无法判断折叠区，不伪造分数。记录复盘卡与姿态finding分开，不给元数据虚构0.6可观测度。仍不据节奏变化自动加量。

验证：41项相关回归通过、npm run build通过。新增用时变化30%、变慢50%、稳定0%、无效条目不拼接、缺用时降级、组间差异、平板/静蹲与上次时长差等测试。393×851隔离浏览器以明确合成草稿走实际“继续上次总结”路径：显示6次、第4–6条1.4秒vs前3条2.0秒、缩短30%、连续变化从第4条开始；复盘卡显示证据，旧无可信评分大字不存在、无横向溢出。非真人动作精度验收，不冒称五段真实记录评审完成。
