# 方案 A v2 — 2026-11-02

## 交付内容

- 首页改为今日建议、腿部／核心／上肢分组与机位提示。按上次同一动作推荐重复训练量，默认计次 3×10、静态 3×30 秒、组间休息 45 秒；支持调整，未推测重量或主观强度。
- 专注训练屏：目标、组数、尝试与未计原因、深度条、分段骨架与深色描边、稳定起始姿势后倒数、组间休息、离开画面 3 秒自动暂停、1 秒长按结束。静态动作以保持时长为主。
- 结束后必经总结。每组使用原 Session 格式与稳定编号；点击“保存并完成”才调用原保存及同步路径。已完成组的本机草稿可恢复，重试不生成新编号。
- 本机低分辨率回放：4 帧/秒，最长 12 秒，最多 10 段、总计不超过 20 MB。选择有最多幅度／节奏／可见姿态提示的片段；无提示时标为普通片段。只进入 IndexedDB，不进入导出或同步。
- 成果卡只有统计文字，无镜头画面。支持系统文件分享，不支持时提供图片下载。
- 记录页显示连续天数、可调整的每周天数目标、近 7 天加权标准率；热力图点击筛选，训练行显示变化；导出移至设置。
- 添加主屏幕 manifest。未加入 Service Worker，不承诺首次断网打开时能加载模型。

## 保持不变与评分边界

原七种动作识别器、`history.ts`、`sync.ts`、云端同步函数没有修改。MediaPipe 模型与置信度配置不变。包裹在识别器之外的训练流程只负责准备、分组、暂停、总结和展示。准备阶段仅用真实稳定帧初始化，避免倒数后第一下漏计，不导入准备阶段次数。

深蹲沿用“有效次数”；其他计次动作沿用既有“完成次数”口径。俄罗斯转体仍为每侧一次，哑铃左右各一次，静态保持与总用时分开保留。

“可见动作标准率”仅根据已有 RepRecord 的有效性、幅度与节奏计算；缺少记录或静态动作显示未评估，不补造全身标准率。躯干前倾、膝盖方向属于 UI 观察提示；膝内扣提示只在可见正面关键点满足条件时出现，不能从侧面可靠判定。阈值需真机继续校验。绿色表示当前可见部位未触发提示，琥珀表示偏差，红色表示暂停／需检查，不作为医学危险诊断。

额外姿态提示次数与回放仅留本机，不扩展 V2.1 云端协议。其他设备仍能读取原训练记录，但不会收到镜头回放或这部分本机附加信息。
